# Issues documented for `school_transport.py`

| Severity | Issue | Type | Line(s) | Description | Fix Approach |
|----------|-------|------|---------|-------------|--------------|
| High | Unsafe shell execution in dispatch alert | Security | 23-24 | `subprocess.run(..., shell=True)` executes a shell command built from user-controlled input (`route`). This creates a command injection risk and is flagged by Bandit (`B602`). | Replace the shell invocation with a safe argument list, e.g. `subprocess.run(["echo", "dispatching bus", route], shell=False, check=False)`, or avoid subprocess entirely for logging. |
| Medium | SQL injection risk in rider enrollment | Security | 8-10 | The `INSERT` statement is built with an f-string, so values like `student`, `route`, `stop`, and `fee` are interpolated directly into SQL. This is flagged by Bandit (`B608`). | Use parameterized SQL: `conn.execute("INSERT INTO riders (student, route, stop, fee) VALUES (?, ?, ?, ?)", (student, route, stop, fee))`. |
| Medium | Bare `except` hides real failure modes | Error handling | 29-32 | `feeCollected()` catches every exception and silently returns `0`, masking actual database or logic errors. This is flagged by Pylint (`W0702`) and Flake8 (`E722`). | Catch a specific exception such as `sqlite3.Error` and handle `None` results explicitly instead of swallowing all errors. |
| Medium | Missing explicit file handling safety | Quality | 17-20 | `exportRoster()` writes to a file without a context manager or explicit encoding, which risks resource leaks and inconsistent behavior. Pylint flags this as `R1732` and `W1514`. | Use `with open(path, "w", encoding="utf-8") as out:` and write within the context manager. |
| Medium | Runtime checks use `assert` | Reliability | 37-39 | `assert feeCollected("R1") == 3600` is not suitable for production validation because assertions are removed under optimization and are flagged by Bandit (`B101`). | Replace the assert with a normal runtime check or a proper test assertion in a test suite. |
